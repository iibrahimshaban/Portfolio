Waslah

solo project

A transportation and route-planning backend that connects passengers with stations, route segments, chained routes, agency trips, and ride requests — plus a standalone ML.NET service for fare prediction.

situation

Passengers travelling across a city often need to cross several routes to reach a destination with no direct line, but typical ride or delivery backends only support a fixed, pre-defined route — there's no way to compute a path between two arbitrary points, and no fare estimate before committing to a ride.

task

Build a way to plan a full trip on demand between any origin and destination, and give the rider a cost estimate up front.

action

Since no single predefined route could cover arbitrary origin-destination pairs, I designed RCBA (Route Chained Builder Algorithm), which finds the nearest station to a location and chains individual route segments together into one multi-leg trip instead of requiring a fixed route between two points. For the fare estimate, I split prediction into its own ML.NET service so it could be retrained and redeployed independently of the main .NET 9 API, taking distance, passenger count, and payment type as input.

result

A rider entering any two coordinates gets a chained, multi-segment route back automatically instead of only a small set of fixed routes, plus a fare estimate before booking — with JWT auth, refresh tokens, and permission-based authorization protecting admin operations underneath.

Architecture notes

  • Layered structure — controllers, contracts (with FluentValidation), services, persistence (EF Core + migrations), and a dedicated authentication layer for JWT and permission policies.
  • Global exception handling returns consistent problem-details responses across the API.
  • Structured request logging via Serilog.
  • Background processing and a protected dashboard through Hangfire.
  • Three-project solution: the main API (.NET 9), the fare prediction service (.NET 8), and a supporting AI/model integration library.
