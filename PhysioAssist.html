PhysioAssist

ASP.NET Core · Angular · Semantic Kernel · SQL Server

A multi-tenant clinic management platform for physiotherapy practices, spanning a clinic-to-doctor hierarchy with bilingual localization. The core of the work is the AI layer — retrieval, transcription, scheduling agents, and documentation — built on Semantic Kernel with routing across NVIDIA, Groq, and Gemini.

situation

Doctors were writing session notes by hand and manually searching paper files for a patient's history, and clinic owners running more than one doctor had no single system to manage them under one account.

task

Build a platform where a doctor could dictate a session and get it documented automatically, and where a clinic owner could run several doctors and branches without duplicating setup for each.

action

For the mixed Arabic/English dictation, generic transcription models struggled with the code-switching, so I routed that specific case through Gemini Flash directly rather than a general-purpose model, and used Semantic Kernel to route everything else across NVIDIA, Groq, and Gemini by task and cost. For the multi-clinic problem, I modeled the hierarchy as Clinic → Doctor sharing one schema, and split scheduling into an immutable TreatmentSchedulePlan versus a mutable PatientSessionPackage, so changing a session doesn't rewrite the original prescribed plan or lose the audit trail.

result

A doctor now gets an AI-drafted note straight from a voice recording instead of typing it, sessions are embedded and searchable across a patient's full history in SQL Server, and one clinic account runs multiple doctors under a shared admin dashboard.

Architecture notes

  • Modular .NET monolith — ASP.NET Core backend, Angular (zoneless, signals) frontend with PrimeNG and Tailwind CSS.
  • Scheduling model splits an immutable clinical prescription (TreatmentSchedulePlan) from a mutable operational child (PatientSessionPackage), with an audit table tracking doctor reassignments separately from per-session substitutions.
  • Embeddings via gemini-embedding-001, stored as SqlVector<float> directly in SQL Server.
  • Auth is JWT with refresh tokens and Google OAuth, with permission-based authorization for receptionist-level access.
  • Deployed on MonsterASP (API) and Vercel (frontend).
