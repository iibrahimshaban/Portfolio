Resort Hub

solo project

A full-featured resort booking system built on ASP.NET Core MVC, covering villa management, availability-aware booking, and role-based access for staff and guests.

situation

A booking form that only checks a date range against a calendar has no idea if that specific villa is already booked for those dates — which is exactly how double-bookings happen in simpler booking systems.

task

Build a booking flow that could not accept a reservation on top of an existing one, with staff and guests kept to separate permissions.

action

Instead of validating a date range in isolation, I check the requested dates against every existing reservation tied to that specific villa in SQL Server before confirming — so availability is relative to that villa's own booking history, not a general calendar check. Role-based authorization on top of ASP.NET Core Identity then separates guest, staff, and admin actions, so a guest account can't touch villa records directly.

result

Staff manage villas and bookings through one role-gated system, live on MonsterASP, and every booking is checked against that villa's existing reservations before confirmation — closing off the most common cause of double-booking in systems that skip that step.

Architecture notes

  • Conventional ASP.NET Core MVC structure with server-rendered Razor views.
  • Availability logic sits at the core of the booking flow, rather than being a simple date-range check — it accounts for existing reservations per villa.
  • Identity-driven authentication with role-based authorization guarding staff and admin actions.
